# 邻传 · NearDrop

一个零第三方依赖的网页局域网传输工具。只需在一台电脑启动 Node.js 服务，同一局域网中的电脑、手机和平板即可用浏览器发送文字、图片和文件，无需安装客户端，也无需注册账号。

## 启动服务

**运行服务的电脑需要 Node.js 20 或更新版本。其他设备只需要浏览器。**

在项目目录打开终端，运行：

```sh
node server.js
```

Windows 可双击 `start.bat`（或它的快捷方式），服务启动成功后会自动在默认浏览器打开页面；macOS / Linux 可运行 `sh start.sh`，也会尝试打开默认浏览器。也可以运行 `npm start`，具有相同的自动打开行为。项目使用 Node.js 内置模块，**无需执行 `npm install`**。

自动打开的地址会使用实际启动端口，自定义 `PORT` 后同样有效。若系统无法启动默认浏览器，服务会继续运行，并在终端提示手动访问地址。只启动服务、不自动打开浏览器时，使用上面的 `node server.js`；也可用 `node server.js --open` 显式开启自动打开。

终端会显示本机地址及可用的局域网地址，例如：

```text
本机：http://localhost:3210
局域网：http://192.168.1.12:3210
```

保持终端运行。关闭终端或按 `Ctrl+C` 即停止服务；请让服务电脑保持开机、联网并避免休眠。

## 其他设备如何访问

1. 将设备连接到同一个局域网，例如同一路由器的 Wi-Fi 或有线网络。
2. 在设备浏览器输入服务电脑终端打印的**局域网地址**，包括 `http://`、IP 地址和端口。
3. 进入相同空间后即可看到在线设备与共享内容。默认进入公共空间，也可以使用相同的六位空间码进入单独空间。

`localhost` 和 `127.0.0.1` 只能用于服务电脑自身；其他设备必须使用服务电脑的局域网 IP。页面中的“使用指南”及“连接另一台设备”入口可查看访问地址；“复制邀请链接”会携带当前空间码。

## 发送与接收

- **文字**：输入内容并发送。同一空间的设备实时收到消息；可以复制文字并主动确认收到。
- **文件与图片**：点击“选择文件”，或从桌面拖入文件，也可粘贴剪贴板中的图片。PNG、JPEG、GIF、WebP 和 AVIF 图片支持页内预览；文件卡片显示名称、大小与上传/可下载状态。可以一次选择多个文件，最多保留 50 个待传文件，并行上传 2 个。
- **传输进度**：上传卡片显示上传到服务电脑的进度与状态。上传完成后，接收方可以下载。
- **失败重试**：网络中断后会尝试自动重试；仍失败时，保留页面和已选择的原文件，再点击对应条目的重试。客户端会向服务端查询已确认的偏移，从该位置继续上传，也支持暂停后继续。上传请求及文字发送使用请求标识，避免因重试产生重复条目。取消的上传无法继续。
- **下载**：点击下载后由浏览器保存文件，下载进度、失败原因和下载重试请在浏览器的下载管理器中查看。大文件不需要先整体加载到网页内存中。
- **接收确认**：查看文字或下载文件后，接收方主动点击确认收到。发送方会看到确认者与确认状态。**上传完成、开始下载或下载结束均不会自动等同于接收确认。**

断点续传适用于当前页面仍持有原文件、服务端也仍保留该传输的情况。刷新或关闭页面会丢失网页对原文件的引用；服务重启会丢失会话与上传偏移。这些情况下需要重新选择文件并重新发起传输。手机浏览器进入后台可能暂停连接，返回前台后会重新连接并同步空间状态。

## 配置

以下配置通过环境变量传入，项目不会自动读取 `.env` 文件。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `HOST` | `0.0.0.0` | 监听全部网卡；设为 `127.0.0.1` 后其他设备无法访问 |
| `PORT` | `3210` | HTTP 服务端口 |
| `MAX_FILE_SIZE` | `2147483648` | 单个文件上限，单位为字节，默认 2 GiB |
| `RETENTION_HOURS` | `24` | 消息与文件的临时保留时长，单位为小时 |
| `MAX_STORAGE_BYTES` | `10737418240` | 暂存文件声明大小的总上限，单位为字节，默认 10 GiB |
| `DATA_DIR` | 系统临时目录下的 `linchuan-transfer` | 上传文件的暂存根目录，运行时会新建独立的 `session-*` 子目录；需要可写且有足够空间 |

PowerShell 示例：

```powershell
$env:PORT = "8080"
$env:RETENTION_HOURS = "12"
$env:DATA_DIR = "D:\NearDropData"
node server.js
```

macOS / Linux 示例：

```sh
PORT=8080 RETENTION_HOURS=12 DATA_DIR=/tmp/neardrop-data node server.js
```

修改端口后，其他设备也需要使用新端口访问。上传经过服务电脑中转，速度取决于网络、磁盘与设备性能；默认单个文件最大 2 GiB，同时暂存容量有服务端保护限制。

## 数据与使用边界

- 文件通过服务电脑中转，并临时保存在其磁盘上；这不是浏览器之间的点对点直传。消息、设备会话与空间索引保存在内存，服务重启后不恢复。
- 内容默认在 24 小时后过期清理，过期后需要重新发送。正常停止服务会提前清空本次暂存；异常退出留下的专用目录会在后续服务运行时检查并按时效清理。服务程序只清理自身管理的临时文件；不要把其他重要文件放到专用数据目录。
- 每个空间最多保存 200 条共享记录。达到上限后，较早的已完成或已取消记录会提前清理；如果全是未完成上传，需要先完成或取消部分传输。
- 默认公共空间中的消息与文件对进入该空间的设备可见；单独空间按空间码隔离。六位空间码用于分组，**不等同于账号身份验证或强访问控制**。
- 服务默认使用 HTTP，没有端到端加密。仅在可信任的局域网中使用，不要配置公网端口转发，也不要用于传输密码等敏感信息。
- 接收文件后请根据来源判断是否安全，再打开或执行。
- 文件下载由浏览器管理；网页无法可靠判断文件是否已经保存到磁盘，因此采用接收方主动确认。

## 无法连接时

1. 确认服务仍在运行，地址来自当前启动日志，IP 和端口输入正确；服务电脑网络变化后 IP 可能改变。
2. Windows 首次提示防火墙时，在可信网络中允许 Node.js 访问**专用网络**。可在系统“允许应用通过防火墙”中检查 Node.js；无需关闭整个防火墙。
3. 确认两台设备处在同一网络；访客 Wi-Fi、无线 AP 隔离、公司网络策略、VPN 或移动数据可能阻止设备互访。
4. 先在服务电脑打开 `http://localhost:3210`（或配置的端口）。若本机也无法打开，请检查终端错误；端口被占用时更换 `PORT`。
5. 下载失败时先在浏览器下载管理器重试；上传失败时保留页面并点击对应条目的重试。内容已过期或服务重启时，需要重新发送。
6. 如果 Windows PowerShell 提示无法运行 `npm.ps1`，可直接使用 `node server.js` 启动，无需更改系统执行策略。

## 项目结构

```text
server.js            HTTP、空间、事件推送、文件与确认接口
public/index.html    页面结构
public/styles.css    桌面与移动端样式
public/app.js        交互与上传、重试逻辑
public/icons.svg     页面使用的本地图标
public/favicon.svg   浏览器标签页图标
start.bat            Windows 启动入口
start.sh             macOS / Linux 启动入口
```

接口采用 HTTP JSON、原始字节分块上传及 SSE。所有消息、文件、下载与接收确认均按会话所属空间校验；上传偏移由服务端确认，文件以随机标识保存，避免直接使用外部文件名作为磁盘路径。
